=== focus.ts ADDITIONS (additive only, do not modify existing code) ===

IMPORTANT: focus.ts must remain pure — NO direct Node.js imports (no 'fs', no 'path', no 'events'). All filesystem operations go through the injected FocusFs interface.

--- FocusFs interface ---

```typescript
export interface FocusFs {
  readFile(path: string): Promise<string | null>;
  watchDir(
    dir: string,
    onChange: () => void,
    onError: (err: unknown) => void
  ): { close(): void };
}
```

- `readFile`: reads file contents as string, returns null if file missing or unreadable
- `watchDir`: watches a directory for changes, calls onChange on any change, onError on watcher error. Returns a handle with close().

--- watchFocusFile ---

```typescript
export interface WatchFocusFileOptions {
  dir: string;
  filename: string;
  fs: FocusFs;
  workspaceId: string;
  onRequest: (request: FocusRequest) => void;
}

export function watchFocusFile(
  options: WatchFocusFileOptions
): { dispose(): void }
```

Behavior:
1. On creation, read the file at `${dir}/${filename}`. If it exists and parses successfully, call `markSeen(request.requestId)` on an internal seen-set (do NOT fire onRequest — this is startup suppression). The internal seen-set is a simple Set<string> or array, separate from FocusQueue.
2. Start watching the directory via `fs.watchDir(dir, onChange, onError)`.
3. On change: read the file, parse with parseFocusFilePayload(parsed, {workspaceId}). If ok and requestId not in the seen-set, fire onRequest(request) and add requestId to seen-set.
4. On error: close the current watcher and re-attach after a delay. Use a timer reference (the timer should be unreferenced so it doesn't keep the process alive — note this in a comment since the caller is responsible for unref'ing in the vscode layer).
5. On dispose: close the watcher, clear any pending re-attach timer.
6. The re-attach delay should be configurable or defaulted (e.g. 1000ms).
7. Guard against double-fire from rapid fs events: use a debounce or a simple "reading" flag so concurrent change events don't trigger multiple reads.

Implementation notes:
- Keep the seen-set unbounded for now — the file watcher lifetime matches the extension lifecycle, so it won't grow indefinitely.
- Parse the file content as JSON. If JSON.parse throws, silently ignore (corrupted/partial write).
- The path join `${dir}/${filename}` is simple string concatenation — no Node path module needed.
